## Problem & user

RocketShip PMs need this handled: Juno's role is to take trancripts, recorsing, help docs, current product and Webex spaces regarding specific product intiatives and turn them into Jira's, figmas and leadership decks. Juno does this inside limits a human set on purpose, and defends every call it makes.

## 01 Context · Data Requirements

**Required sources, and exclusions**

Webex help docs, current figmas, meeting recordings and Webex spaces

**How fresh must it be**

these are current docs and current conversations so it's always fresh , do not look at communication before 6 months ago

## 02 Tools · System Capabilities

**The verb list**

create a detailed Jira with requirements, a figma for the product and a leadership deck about the initiative

**Deliberate omissions**

Only create Jira issues in the Spark project.
Set only Summary and Description.
Don’t add labels, assignees, or other fields.
Don’t publish to another Jira project or an unrelated destination.
Check the requested output format: Jira ticket, Word document, or slide deck.

## 03 Loop · AI Costs & Latency

**Turn ceiling and escalation**

cap gather, draft, and verification passes; retry once, then escalate.

**Latency and cost target**

caps work at four model turns and one retry, measures latency and cost across the whole task, and requires a clear partial result if a time or budget limit is at risk

## 04 Memory · Data Requirements

**What persists, at what scope**

keep run data temporary; persist only owner-approved, dated knowledge.

**Expiry and write rules**

Authenticated human corrections override model summaries immediately, while preserving the prior value for audit. If a correction conflicts with cited evidence or comes from someone without authority, Juno shows both and asks the designated owner

## 05 Permissions · AI Risks & Mitigations

**The permission tier**

| Side-effect class | Tier |
|---|---|
| read | confirm |
| draft | auto |
| write | confirm |
| send | confirm |

**Justification**

allow reads and drafts; require approval before creating an issue.
the blast radius and undo limits for each tier: read, private draft, Spark issue creation, and denied sharing or other-project writes.

## 06 Verification · AI Testing & Measurement

**The check before output ships**

check citations, testable criteria, dependencies, risks, destination, and the saved issue.

**Failure behaviour**

report passed and blocked items, explain the failed check and next step, preserve valid work, allow one safe retry, and clearly surface unresolved issues. A Jira write mismatch is disclosed with its issue key; it is never silently retried.
